# 07 — Accessibility and best practices

## Practical checklist

- Use semantic HTML where possible.
- Give meaningful images useful `alt` text; use empty alt for decorative images.
- Associate every form field with a label.
- Use headings in a logical hierarchy.
- Ensure controls work with a keyboard.
- Provide visible focus styles.
- Use descriptive link text.
- Give iframes a meaningful title.
- Do not rely on color alone to communicate meaning.
- Test zoom, responsive layouts, and browser accessibility tools.

## Buttons vs links

Use `<a>` when navigating to another location. Use `<button>` when triggering an action on the current page.

## IDs and classes

`id` should identify a unique element in a document. `class` can be reused. Avoid duplicate IDs.

## Debugging and validation

1. Inspect the page in developer tools.
2. Check the console.
3. Inspect the DOM.
4. Validate markup with the Nu HTML Checker.
5. Test keyboard navigation and responsive layouts.

## Practice
Audit one of your pages and list five accessibility improvements.
